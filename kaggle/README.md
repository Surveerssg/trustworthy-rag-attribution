# Running on Kaggle (free: GPU T4 x2, 30 GPU-hours per account per week)

`trag_kaggle_stage2.ipynb` is generated by `build_stage2_notebook.py` (edit the builder, then `python kaggle/build_stage2_notebook.py`).
`trag_kaggle.ipynb` is the notebook of the mid-sem core run (kept for provenance; do not re-run).
No API keys are used anywhere on Kaggle. Keep every dataset and notebook **Private**. All parts below are done; their output zips are in
`experiments/kaggle_raw/`.

## Part G: run it (after Part F, since one account runs at most two sessions at once; about 9-10 GPU-hours in total, estimate)
1. `python -m scripts.make_kaggle_bundle` (the bundle now also holds `data/plans/bioasq.jsonl`); upload it as a **new private dataset**.
2. Notebook G1: `PART = "E"`, `E_JOBS = ["bq_qwen32b", "bq_mistral24b", "bq_qwen14b", "bq_qwen1.5b"]`, `E_BUDGET_H = 8.5`, `E_NAME = "G1"`.
   Notebook G2: `PART = "E"`, `E_JOBS = ["bq_gemma27b", "bq_phi4", "bq_llama8b"]`, `E_BUDGET_H = 8.5`, `E_NAME = "G2"`.
   Same settings and checks as Part E (each job: 800 answers, then NLI scoring at the end of the session).
3. Ingest both zips, then `python -m scripts.analyze_bioasq` (pre-registered B1-B5, `paper/findings/analysis_plan_bioasq.md`).
   Estimate from the TAT-QA timings (600 answers): G1 about 4.5 h, G2 about 4 h of generation.

## Part F: run it (two sessions at the same time on one account, about 8-10 GPU-hours in total, estimate)
1. Build the bundle: `python -m scripts.make_kaggle_bundle` -> `dist/trag_bundle.zip` (134 files, it includes `data/llm_attr/`). Upload it as a
   **new private dataset**. The notebook is `kaggle/trag_kaggle_stage2.ipynb`. Those two files are all Kaggle needs.
2. Notebook 1 (the main judge): first cell `PART = "E"`, `E_JOBS = ["attr_qwen32b"]`, `E_BUDGET_H = 10`, `E_NAME = "F1"`.
   Notebook 2 (the cheap judge): `PART = "E"`, `E_JOBS = ["attr_llama8b"]`, `E_BUDGET_H = 10`, `E_NAME = "F2"`.
   Both: GPU T4 x2, Internet On, only the new dataset attached, Save Version -> Save & Run All (Commit).
3. After about 30 minutes check the log: `job 1/1: attr_qwen32b (qwen2.5:32b) | 12008 answers to generate`, `pull ... exit 0`,
   `in GPU memory` about equal to `total`, then `[E attr_qwen32b .. min] n/12008 answers | r per hour | ETA`. The judge writes one passage number
   per sentence, so it is much faster per item than generation; the ETA line is the real estimate (none is measured yet).
   Datasets are judged in priority order (FinanceBench, TAT-QA, CUAD, PubMedQA, HotpotQA, SQuAD), so a cut-off loses the least important part.
4. Download both zips into `experiments/kaggle_raw/`, then
   `python -m scripts.ingest_kaggle experiments/kaggle_raw/trag_results_stage2E_F1.zip --no-analyses` (and F2), and
   `python -m scripts.analyze_llm_attributor` (pre-registered L1-L4, `paper/findings/analysis_plan_llm_attributor.md`).
   If a job is PARTIAL, resume as in step 5 below; the analysis already works on what was judged and says how many sentences that is.

## How to run any part
1. `python -m scripts.make_kaggle_bundle` (allowlist + secret scan) builds `dist/trag_bundle.zip`. Upload it as a **new private dataset**
   (do not unzip). The notebook finds the code by the `trag_bundle/` folder inside, so the dataset name does not matter.
2. Create → New Notebook → File → Import Notebook → `kaggle/trag_kaggle_stage2.ipynb`. Add Input → that dataset (only that one).
   Settings: Accelerator **GPU T4 x2**, Internet **On**.
3. Edit only the first cell (`PART` and that part's settings), then Save Version → **Save & Run All (Commit)**.
4. Download the output zip into `experiments/kaggle_raw/`, then `python -m scripts.ingest_kaggle experiments/kaggle_raw/<zip> --no-analyses`
   (checks completeness against each run's own `config.yaml`).
5. **Resume** (Parts D and E stop cleanly at their time budget, the log says `[deadline]` / `PARTIAL`): run again with **Add Input → the previous
   version's output** attached as well; finished answers are reused.

## Part D / E settings and safeguards
- Part D: `D_MODEL`, `D_LIMIT = 100` (questions per domain, nested seeded subsample), `D_BUDGET_H`, `D_KV_Q8` (only if the model does not fit),
  `D_NO_LOGPROBS` (only if a model returns no log-probs).
- Part E: `E_JOBS` = config names `configs/kaggle_<job>.yaml`, run in order: `v2_<model>` = the Part D subset with a new model,
  `tq_<model>` = TAT-QA (oracle_vanilla, removed_trust, oracle_trust). `E_BUDGET_H` = generation budget for all jobs (keep about 1.5 h of the 12 h
  cap for setup, scoring and zipping). `E_NAME` = zip suffix. A job whose model does not fit in GPU memory is retried with a q8 KV cache; a model
  that returns no log-probs is run without them; a failed download marks only that job FAILED. Each model is deleted after its last job to free disk.
  The run used: session A `["v2_mistral24b", "tq_mistral24b", "tq_qwen14b", "tq_qwen1.5b"]`, session B
  `["v2_phi4", "tq_qwen32b", "tq_llama8b", "tq_phi4", "tq_gemma27b"]`, both `E_BUDGET_H = 8.5`.
- A 24-32B model must be split over both T4s (one Ollama server, `OLLAMA_SCHED_SPREAD=1`); a 14B model fits on one.
- Kaggle's Python may be older than 3.12: no backslashes inside f-string expressions in notebook cells.
- Timing guide from the logs: on two T4s, about 10-14 s per answer for 24-32B models, 3-4 s for 14B, under 2 s for 8B and below.
